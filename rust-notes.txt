====================================
Rust 공부 노트
====================================

이 파일은 배울 때마다 이어서 채워짐.

------------------------------------
[1] 왜 Rust인가 — 안전 철학
------------------------------------

C의 큰 문제 두 가지:
  1) 버퍼 오버플로우 (배열 밖에 써버림)
  2) use-after-free (반납한 메모리를 또 씀)
둘 다 공격자가 프로그램을 조종하는 통로.

각 언어의 답:
  - C     : "네가 알아서 해." → 뚫림
  - Java/C#/Python : 가비지 컬렉터가 실행 중에 청소 → 안전한데 느림, 예측 불가
  - Rust  : 컴파일 때 규칙으로 강제 + 실행 중 검사도 병행

Rust의 방식은 두 갈래:
  - 컴파일 때 알 수 있는 것 → 컴파일 거부 (소유권/빌림)
  - 실행해봐야 아는 것    → 실행 중에 panic으로 즉시 중단

배열 인덱스 예:
  let arr = [1,2,3,4,5];
  let i = 10;
  arr[i];   // 💥 panic: index out of bounds

C는 그냥 옆칸 덮어써서 뚫림 → 조종당함.
Rust는 그 자리에서 멈춤 → 최악(조종당함)을 중간(그냥 꺼짐)으로 바꾼 것.

------------------------------------
[2] 소유권 (Ownership) — 컴파일 때 막는 것
------------------------------------

핵심 규칙:
  "모든 값은 주인이 딱 한 명. 주인이 사라지면 값도 같이 사라진다."

예시:
  let s1 = String::from("hello");   // s1이 주인
  let s2 = s1;                      // 주인이 s2로 넘어감 (move)
  println!("{}", s1);               // ❌ 컴파일 에러
  // error: borrow of moved value: `s1`

이 규칙 하나로 C의 세 가지 문제가 통째로 사라짐:
  - 안 치움      → 주인 죽을 때 무조건 치우므로 불가능
  - 두 번 치움   → 주인이 하나뿐이므로 불가능
  - 치웠는데 씀 → 주인 죽으면 그 이름도 못 씀

전부 실행 전(컴파일 때)에 잡음 → 실행 중 검사 없음 → C만큼 빠름.
